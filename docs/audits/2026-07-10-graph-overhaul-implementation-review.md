# Graph overhaul implementation review — full findings

**Date:** 2026-07-10

**Scope:** correctness review of the implemented knowledge-graph overhaul (commits through `f086180`) against `docs/superpowers/specs/2026-07-09-knowledge-graph-retrieval-overhaul-design.md` and the audit `docs/audits/2026-07-09-knowledge-graph-retrieval-review.md`. Five parallel deep reviews (indexing/build, graph layer, shared retrieval engine, live path, chat path) plus independent verification of every critical/high claim.

**How to read:** every finding has a stable ID and a `Status`. `open` = needs work; `fixed` = verified resolved; `accepted` = deliberate trade, no action planned. Items are removed or marked fixed as remediation lands (see `docs/superpowers/specs/2026-07-10-graph-overhaul-fixes-spec.md`).

---

## Executive summary

The implementation is a faithful, well-engineered port of roughly 85% of the overhaul spec. Deterministic atomic builds, projection isolation, dangling-correct PPR, directed temporal facts, query-to-triple seeding, the evidence registry, and six-stage citation validation are all real and unit-tested. Audit findings G4 (double counting), G5 (rebuild drift), G8 (direction loss), R2 (fake triple seeding), R4 (transcript delta loss), and R5 (dangling PPR) are verified fixed in the production path.

But the system as reviewed had three ship-blocking runtime defects — retrieval crashed on entity-bearing queries (since fixed in `f086180`), chat's primary tool flow dies on a registry payload conflict, and the live summary pipeline deadlocks after its first accepted rolling summary. All three share one root cause: **unit tests exercise fakes whose shapes diverge from production wiring, and no integration test runs the real seams.** Beneath them sit data-quality defects (acronym entity merging, saturated graph weights, a stale-prone extraction cache) and a program-level gap: the calibration/evaluation loop (spec Unit 0 / §18) has never been run, so the abstention machinery runs on hand-authored floors fit to zero labeled samples.

## Part 1 — Assessment of the spec and audit themselves

The 2026-07-09 audit is evidence-based and its diagnoses are all real. The spec is a sound, unusually complete response; its architecture decisions (base-graph/projection split, disposable knowledge DB, no-migration regeneration, deferral of GNN/communities/ANN) are correct at this scale. Spec-level holes, several of which directly caused implementation bugs:

| ID | Hole | Consequence |
|---|---|---|
| S1 | Cutover-before-calibration: §18 gates are mandatory for release, but §1.2 mandated deleting the old system with no rollback, and the artifact was allowed to ship "seeded." | Production runs an uncalibrated retriever; abstention behavior unproven (see P1). |
| S2 | Rolling-summary availability semantics unspecified: §13.6 feeds the prior summary in but never says how carried-forward citations satisfy availability. | Caused C3a (live summary deadlock). |
| S3 | Trigger/abstention interaction unspecified for meetings with no KB overlap; §13.6 supports transcript-only summaries but nothing says triggering must not depend on retrieval acceptance. | Caused C3b (sessions that never summarize). |
| S4 | No degenerate-distribution gate on graph weights; §10.2's `calibrated_clip` range undefined. | Caused H2 (contains-weight saturation). |
| S5 | Rerank-cap candidate ordering unspecified in §11.10. | Caused H6 (incomparable score-family mixing). |
| S6 | Registry payload-identity semantics undefined for the same passage arriving via different routes. | Caused C2 (chat tool registry conflicts). |
| S7 | §17.3 head isolation specified but absent from the §20 test list. | Caused H-B2 (one broken head kills every query). |
| S8 | Feasibility left unpriced: single-user labeling burden for five datasets; per-query temporal graph overlay cost unbounded against the 750 ms live budget. | P1 unstarted; L30 latency risk. |

The spec's one philosophical bias: aggressively precision-first (NLI gating, strict availability, fail-closed everywhere) with no graceful-degradation story when validation over-rejects. Product decision recorded 2026-07-10: **live stays strict (nothing unsure is shown); chat gets a liberal fallback profile** (low-confidence evidence explicitly marked, readier fallback) — see the fixes spec.

## Part 2 — Indexing pipeline as implemented (verified map)

Production flow: sync button → `sync_all_enabled` (source-record cache refresh only, in legacy `taurine.db`) → `regenerate_knowledge` → `BuildCoordinator.build` (fresh `taurine-knowledge.build-<id>.db`) → invariant validation + graph hash → atomic `os.replace` install → `RetrievalRuntime.activate_from_disk` (single immutable `IndexSnapshot`).

Build stages: deterministic build_id → token-aware passages (Qwen tokenizer, 220/300/40) + FTS → passage embeddings via content-keyed `BuildCache` → GLiNER2 `batch_extract`/`batch_extract_long` with spans, per-note failure isolation → union-find entity resolution → bounded LLM relation-completion lane → temporal fact reconciliation → base graph (passage+entity nodes only; directed fact edges with reverse-traversal weights; semantic top-k union) → derived note projection (max-spanning forest + degree-12 fill) → quality/value ranks → fact embeddings → validation → install. Incrementality lives in the caches; graph finalization is full and deterministic (`rebuild_for` removed; double-build hash-equality tested).

Legacy status: §23 deletion done 2026-07-10 (W3-F). `indexer/sync.py` (including the legacy CLI footgun), `adjudicate.py`, `graph.py`, `rank.py`, `slim_enrich.py`, and `core/migrate_enrichment.py` are deleted; `SyncReport` moved to `schemas.py`; `source_rank`/`recency_multiplier` moved to `indexer/priors.py` (build.py consumer); `communities.py` kept its production `projection_communities`/`label_propagation` (now self-contained, no `NoteGraphMatrix`). `store.py` remains as the product store, trimmed to product surface only (source-record cache, connector state, salience ledger, chat store, user card, `preview`/`graph`/`aliases`/`status`); the legacy dense/BM25/fact search, enrich cache, edge/term/judgment writers, and quality/value rank persistence are gone. Deliberately kept: `GLINER_CHUNK_SIZE`/`GLINER_CHUNK_OVERLAP` aliases (still read by `extract.py`/`build_cache.py`), the legacy `taurine.db` schema DDL (product functions still read/delete those tables), and `live/exact.py`'s `IndexPort`/`aliases()` seam (module itself currently has no production caller).

## Part 3 — Findings

### Program-level

**P1 — Calibration/evaluation loop never run.** `core/evals/graph_retrieval/calibration-v1.json` has `sample_count: 0`, `held_out: {}` on every curve; the labeled datasets, curve fitting, and §18 ablation/release gates (Unit 0) have not been executed. Every floor (dense 0.70/0.62, BM25 0.75, triple recognition 0.82/0.74, evidence 0.75/0.65, NLI 0.8) is an unvalidated guess. The eval harness exists (`evaluation/graph_retrieval.py`). Requires user labeling effort; not automatable. `Status: open (user-dependent)`

### Critical

**C1 — Retrieval crashed on entity-bearing queries.** `runtime._resolve_entity` returned a private `_EntityResolution` wrapper that `heads._resolution_candidates` mis-consumed (`.entity_id` on `RawHeadCandidate`) → `AttributeError` killing the whole `retrieve()` for chat and live whenever a query span matched a known alias. `Status: fixed` in `f086180` — resolver returns a plain `RawHeadCandidate` tuple (Sequence pass-through branch, identical ambiguity semantics), object branch hardened, end-to-end regression test added. Fix reviewed and verified 2026-07-10; also moots the latent always-ambiguous defect (`status="missing"` path no longer taken).

**C2 — Chat tools fail on registry payload conflicts.**
- `read_note`: a full (non-excerpt) passage registers under the same identity as Stage A's engine registration but with an extra `excerpt: False` payload key (`chat/retrieval.py:442-452` vs `retrieval/evidence.py:608-617`); `registry.register` raises on payload mismatch (`registry.py:52-53`) and the tool returns `{"error": ...}` to the model. The most common flow — "read the note you just cited" — is dead. Tests dodge it because their budgets force excerpt-suffixed identities.
- `expand_evidence`: `_register_traversed_facts` (`chat/retrieval.py:599-617`) re-registers facts without a `ref_for` guard, with single-row `fact_ids`/`source_evidence_ids`/`observed_at` that mismatch the engine's grouped registration (`evidence.py:911-938`) → `ValueError` → whole tool call fails, intermittently (multi-provenance facts).
`Status: fixed` (read_note full passages and traversed facts go through `ref_for` guards plus the shared `evidence_payloads` helpers — canonical passage payloads and engine-grouped fact identities from the snapshot fact index; real-registry integration tests over a `BuildCoordinator` build cover read-after-cite and multi-provenance expansion)

**C3 — Live summaries deadlock / never start.**
- **C3a (rolling-summary rejection):** `summarizer.py:132-142` validates with `available_ids` = current pass support + current snapshot T# only. The prior accepted summary (with embedded citations) is prompt input and the result wholesale-replaces it, so carried-forward sentences keep citations that fail availability → whole summary rejected → checkpoint never advances → every retrigger rejects again while unsummarized chunks grow unboundedly. Old T# can never re-enter `valid_ids`.
- **C3b (trigger cold-start):** every arm of `_change_reason` (`trigger.py:89-104`) needs state that only exists after a first pass (accumulated ids; an embedding never passed — `ingest.py:186` passes `None`; `_last_pass_at` set only by `note_summary`/`note_rejected`). A session whose retrieval always abstains (no personal-KB overlap — the common case) produces zero summaries ever, despite §13.6 explicitly supporting transcript-only `T#` summaries.
`Status: fixed` (C3a: per-session accepted-citation ledger in `Summarizer` — refs cited by the last accepted summary stay in `available_ids` while they resolve with payload text, pruned wholesale on each acceptance; C3b: staleness measures from session start, a `first_summary` arm fires until the first accepted summary, and the window embedding is now passed to the trigger)

### High

**H1 — Acronym matching transitively merges distinct entities.** `entities.py:287-290`: any ≤5-char compact surface equal to another surface's initials merges, no uniqueness requirement; union-find transitivity bridges "John Smith" ↔ "JS" ↔ "Jane Stevens" into one entity canonicalized as "JS" (shortest-on-tie, `entities.py:217-226`). All facts of both people fuse; exclusive-predicate reconciliation can mark two people's facts as superseding each other. Violates §7.2 and the §18.2 merge-precision ≥0.98 gate. `test_entities.py` covers only the benign one-referent case. `Status: fixed` (acronym→expansion uniqueness map built before union-find; short↔expansion unions only, ambiguous acronyms stay separate entities with alias-level ambiguity; canonical prefers the expansion)

**H2 — Contains weights saturate at 1.0; §10.2 is inert.** `base_graph.py:119-121` + `_clip` at `:343`: with df eligibility caps, `idf ≥ ~1.69`, `count_bonus ≥ 1.69`, confidence ≥ 0.5 ⇒ product ≥ ~1.43 ⇒ every production contains edge clips to exactly 1.0. Consequences: (a) passages distribute equally to all entities after column normalization — idf rarity discrimination gone; (b) projection entity mechanism (`strengths[l] × strengths[r]`, `projection.py:71`) pins any note pair sharing any eligible entity at 1.0, degenerating edge selection into note-id tie-breaking under the degree cap. Even the test only asserts `> 0.8`. `Status: fixed` (contains weight = clip01(idf × conf × bonus / `CONTAINS_WEIGHT_SCALE`=6.0) — rare entities now outweigh common ones and mid values land 0.3-0.7; build report carries contains-weight distribution stats and >80%-identical-weights marks health degraded with reason `degenerate_contains_weights`)

**H3 — Live session accumulator: no decay, no cap, no prune; topic-shift path dead.** `grounding.py:92-124` accumulates accepted evidence forever; `session_reset()` feeds every passage ever accepted at full `rerank_score` into PPR teleport each pass (`SESSION_RESET_W=0.35`). The `topic_shift` parameter exists but the only production call is `on_pack(pack)` (`ingest.py:164`) and nothing computes topic shifts. §13.3 unimplemented; audit R7's contamination half regressed (fixed 0.85 decay → no decay at all). Stale topics also keep `_top_ids` static, suppressing the trigger's jaccard arm. `Status: fixed` (accumulator decays by `LIVE_ACCUM_DECAY` per accepted pass, per-note cap `LIVE_ACCUM_NOTE_CAP`, epsilon prune; abstention freezes state; topic shift detected in `AmbientRetriever` via query-embedding-vs-EMA cosine < `LIVE_TOPIC_SHIFT_SIM` and wired into `on_pack(topic_shift=True)`; incumbents flagged `prior_context`)

**H4 — Calibration integrity is ceremonial.** `runtime.py:94-100` passes the artifact's own hash back to itself (tautological); the `hash` field (`"sha256:initial-conservative-2026-07-09"`) is a label never recomputed from content (`evaluation/graph_retrieval.py:201-202`) — editing floors silently passes all checks. Mismatch behavior also diverges from §11.3: hard-fail (`CalibrationMismatch`/`ValueError`) instead of degrade-to-conservative-floors with a mismatch status. `Status: fixed (content-hash verification in load_calibration, artifact hash regenerated, runtime degrades to in-code conservative floors with calibration_mismatch status)`

**H5 — Extraction cache key omits real inputs.** `build_cache.py:224-245` fingerprints `config.INGEST_ENTITY_TYPES` + `facts.PREDICATES` descriptions, but the schema actually sent to GLiNER2 is built from `INGEST_RELATION_TYPES` templates + family emphasis (`extract.py:745-754`), and per-type acceptance/promotion thresholds are baked into cached payloads. Editing prompts, chunk sizes, model version, or recalibrating thresholds silently keeps stale extractions until a manual `_EXTRACTION_CACHE_VERSION` bump. Reintroduces the G7 stale-state class one level up. `Status: fixed` (`_schema_fingerprint` now hashes rendered per-family relation schemas, entity descriptions, chunk/overlap knobs, extractor model id, and the loaded calibration threshold tables; `_EXTRACTION_CACHE_VERSION` bumped to v2)

**H6 — Rerank-cap ordering mixes incomparable score families.** `_candidate_scores` (`evidence.py:733-749`) sets `recall_score = max(fused_RRF (~0.08), PPR mass (≪1), triple support (≥0.72), path weight (≤1))`; the reranker cap (30/60) sorts by it (`rerank.py:86-91`). Graph-expanded passages with weight ~0.8 outrank every direct dense hit, so the strongest calibrated dense evidence can be evicted from reranker input by weak expansions. Also makes `EvidencePassage.retrieval_score` semantically incoherent. `Status: fixed (tiered rerank-cap ordering: direct calibrated > triple support > PPR/path; component scores kept separate on candidates)`

**H7 — Cancelled/errored chat turns fabricate provenance and advance state.** `persist_turn` always runs `_finalize_evidence` (`engine.py:280-292`); a cancelled partial fails coverage → all sentences stripped → `_evidence_excerpt` replaces content AND `mark_cited`s the top-3 Stage A passages (`engine.py:948-958`), persisting `cited_ids` for an answer the user never received; the persisted message differs from what streamed. Also failed/cancelled turns advance and persist the accumulator (`chat/retrieval.py:124-131` + `engine.py:322-323`), violating §14.5's accepted-turn keying. The cancel test passes only via a test-only bypass (`engine.py:894-898`). `Status: fixed` (cancelled/errored turns persist the raw partial with `interrupted=True`, cite nothing, skip validation/excerpt, and restore the retriever's pre-turn snapshot; accumulator advancement moved to `commit_turn` after accepted finalization; the registry-None bypass removed, cancel tests use a real registry)

**H8 — Relation-completion lane loses most of its recall.** `build.py:322-336` emits one `CompletionEntity` per mention; `relation_completion.py:119` collapses `{entity_id: row}` last-wins to one arbitrary span; validation (`:128-139`) then requires that span inside the LLM's assertion → facts grounded against any other occurrence of a multi-mention entity are rejected (counted only in `completion_rejected`). Exactly the entity-rich notes the lane targets lose recall. Tests use single-mention entities. `Status: fixed` (all mention spans kept per entity; a fact is accepted when any subject×object mention pair grounds inside the assertion, recording the tightest pair's offsets)

**H-B2 — No per-head failure isolation (§17.3).** `evidence.py:237-293` runs dense/bm25/exact/entity/triple bare; any exception kills `retrieve()`. `HeadResult.status` field exists but is never set; `AbstentionPolicy` has no unavailable-heads input. One corrupted FTS index turns every query into a hard failure instead of degraded dense-only retrieval. `Status: fixed (per-head isolation with HeadResult.status, sanitized errors in trace debug, strict 1.1x degraded floor in pre_ppr, all_heads_unavailable abstention)`

### Medium

**M1 — Assertion-span paragraph fallback off-by-one.** `extract.py:662`: `text.rfind("\n\n", 0, left) + 2` yields 1 when no blank line precedes → relations whose subject is the note's first word are silently dropped (`paragraph_start(1) <= left(0)` fails); others get off-by-one stored offsets. Verified. `Status: fixed` (`rfind` sentinel handled: paragraph_start is `idx+2` only when `idx>=0`, else 0; first-word-subject and mid-document offset tests added)

**M2 — Temporal incoherence across recall/graph/paths; conflicted facts never presentable.** Triple recall admits historical/superseded under `"any"`/`"at_time"` (`triples.py:516-544`) but the PPR overlay only admits `status=="active" and valid_at` for every non-historical intent (`evidence.py:1069-1087`) and `paths.py:132-140` rejects non-active — recognized historical facts seed entities whose edges don't exist and can never render on a path (§11.9 violated). `historical` intent without timestamp keeps only historical/superseded, hiding active facts whose validity covers the asked-about past. `conflicted` is unconditionally excluded (`evidence.py:1073`) — §8.3's present-the-conflict branch unimplemented. `Status: fixed (one shared fact_temporal_admission predicate for recall/overlay/paths; historical admits past-covering active facts; conflicted presented flagged under historical intent or both-endpoints seeding, never traversed)`

**M3 — Entity resolution O(n²) + resolution stages 5-6 unwired.** `entities.py:121-129` compares every same-type mention pair with regex work per call: measured 8.1 s at 5k mentions, quadratic (≈2 min at 20k) — against the 60 s finalization gate; an iMessage+email corpus easily reaches tens of thousands of mentions. Also §7.1 stages 5-6 (embedding candidate generation + lexical/context verification) never run: `build.py:255` constructs `EntityResolver` without a similarity function. `Status: fixed` (mentions bucket by (etype, normalized) — 20k mentions resolve in ~0.13 s; stages 5-6 wired via a build-embedder surface-similarity callable at `ENTITY_EMBED_SIM`=0.95, guarded by lexical/digit/type checks and a person last-name+containment rule)

**M4 — Salience never reaches the knowledge build; no quality gating.** Connectors compute `ingest_salience` (`registry.py:122-132`; email funnel) and the knowledge schema has the column, but `BuildCoordinator` never passes it (always 1.0) and `_compute_note_ranks` (`build.py:717-728`) omits it from value — §9.1 stage 2 unfulfilled; the §6.6 completion gate degenerates to recency×source_rank. More broadly there is no build-time quality gating at all: every connector record is passaged, embedded, and extracted regardless of salience or content quality. `Status: fixed` (connector salience rides `NoteRecord.ingest_salience` into the build; `indexer/salience.py` computes deterministic content quality; `note_salience = ingest × quality` stored on the note row; notes below `EXTRACTION_SALIENCE_FLOOR`=0.35 get `extraction_status='skipped_low_salience'` — passages/FTS/embeddings always built, GLiNER/mentions/facts/graph participation skipped, re-evaluated each build; value scores multiply in salience; build report carries gated counts per source + salience distribution)

**M5 — Retrieved/consulted collapse in chat persistence.** `turn_pack` overwrites both with the turn's read refs (`chat/retrieval.py:329`) so `retrieved_ids == consulted_ids` in every persisted message; §12.4's three-set contract degenerates and the candidate set is unrecoverable. `Status: fixed` (`turn_pack` preserves the Stage A trace's `selected_ids`; persisted messages and session-log records carry retrieved = Stage A candidates, consulted = read refs, cited unchanged — wire format backward compatible)

**M6 — Evidence block advertises fact-support `[E#]` refs the validator rejects.** Non-selected fact-support passages are registered but never marked read or included in `available_ids` (`evidence.py:642-658`, `engine.py:904-910`), yet the prompt renders `supported by [E3]` (`engine.py:838-843`) — citing them strips the sentence as `evidence_unavailable`. `Status: fixed` (`expose_fact_support` marks ≤1 non-selected support passage per fact read, ≤4 per pack, rendered as a title+snippet quote under the fact; the evidence block advertises only citable support refs)

**M7 — Entity-derived passage reset double-counts.** `evidence.py:335-340`: every passage mentioning any resolved entity gets `max(existing, global-max entity weight × QUERY_ENTITY_RESET_W)` in `passage_reset`, while the same entities also enter teleport as entity nodes — entity evidence counted twice, and a weakly-resolved entity's passages inherit the strongest entity's mass. Was masked by C1; C1's fix activates it. `Status: fixed (passage-reset injection from resolved entities removed; entity mass flows only via query_entity_reset; recall verified by tests without a replacement bonus)`

**M8 — Ledger/session lifecycle.** `_run_summary` catches only `Exception` (`ingest.py:214-224`), no `try/finally reject_summary` — task cancellation (`CancelledError`) leaves `in_flight_through_seq` set while `_summary_task` clears → next trigger raises `RuntimeError` out of `on_chunk`; summaries permanently dead for the session. On websocket disconnect the server neither cancels nor awaits the in-flight task (`server.py:683-692`) — orphan task logs into a closed `SessionLogger`. `Status: fixed` (`_run_summary` settles the checkpoint on every exit path including `CancelledError` via a settled-flag `finally`; idempotent `LiveSession.aclose()` cancels+drains the task; server disconnect handler awaits it before `logger.close()`)

**M9 — Actionable confirm/dismiss reverted by stale snapshot.** `open_actionables` snapshotted at trigger time (`ingest.py:199-201`); user status changes during the LLM call are overwritten by `_merge_actionables` re-stamping from the stale snapshot (`ingest.py:252`, `summarizer.py:389-405`). `Status: fixed` (`LiveSession` tracks user-set statuses and re-applies them with precedence over the summarizer's merge at acceptance and on emitted actionable events)

**M10 — CLI violates the §22 contract.** `build.py:590-628` exits 0 and installs on release-gate failure; and CLI builds are always degraded because `main()` never wires a relation completer (`build.py:617-621` → `relation_completion_unavailable` blocker at `:498-499`). False green for release verification. `Status: fixed` (CLI exits 2 on build/invariant failure without installing, exits 3 with blockers printed when the installed build is not release-ready — `--install-degraded` accepts that as 0; a relation completer is wired from the shared `relation_completer_for` construction when `OPEN_ROUTER_API_KEY` is configured; `--no-relation-completion` skips it intentionally and downgrades the blocker to a warning)

**M11 — §14.4 evidence-sufficiency check missing.** Only a budget-exhausted notice exists (`engine.py:430-443`); no computed sufficiency signal before the final no-tools round. `Status: fixed` (deterministic `evidence_sufficient` on the retriever — the turn base's calibrated acceptance, tool packs included; the forced no-tools round injects an explicit state-the-gap nudge when nothing cleared the floor)

**M12 — Sentence classifier bypass.** `validate.py:26-30, 278-283`: sentences starting "here's what I found…"/"I can help…"/"I think…" are classified non-factual — "Here is what I found: the launch moved to July 18" passes with zero citations. No labeled fixture set exists (§12.3 requires one). `Status: fixed` (a prefix match only exempts when no factual tail follows a colon/comma boundary — the remainder is classified independently once; "may" hedges lowercase-only so month dates stay factual; `tests/fixtures/sentence_classes.jsonl` with 42 labeled sentences and a ≥0.95-accuracy / zero-false-exempt test)

**M13 — Hub policy: no query-time activation; decisions not persisted or reported.** `activate_entities` (`base_graph.py:93`) has no production caller and hub contains-edges are never persisted, so a query explicitly naming a hub entity cannot traverse it (§10.5's temporary enablement unimplemented). `EntityResolver` computes `traversal_reason` but `build.py:257` drops it and the build report hardcodes `"document_frequency_hub"` for all exclusions (`build.py:480-484`). `Status: fixed` (query half: explicit hub seeds synthesize capped contains edges per query (§10.5); build half: `traversal_reason` persisted on entity rows and exposed via `EntityContext`, and the report's `hub_exclusions` carries the real per-entity reason — date_default_off / pronoun / concept_stoplist / owner_alias_hub / document_frequency_hub)

**M14 — Quality-rank same-source duplicate guard missing.** `_compute_note_ranks` (`build.py:661-729`) has no `DUP_EDGE_SIM` exclusion (legacy-only, `rank.py:63-65`); near-duplicate same-source notes form mutually-reinforcing cliques inflating quality rank. Same-source near-duplicate flagging (§10.4) absent everywhere in the new build. `Status: fixed` (same-source projection edges with semantic mechanism ≥ `DUP_EDGE_SIM`=0.92 are excluded from the quality PageRank matrix — kept in the projection for display — and flagged in `BuildReport.near_duplicate_note_pairs`)

**M15 — Hub path penalty unwired.** `EvidencePathFinder` supports `hub_entity_ids` (`paths.py:29, 109-110`, tested) but the engine constructs it without the argument (`evidence.py:393-397`) — §11.9's hub penalty never applies. `Status: fixed (engine passes snapshot-derived hub_entity_ids (minus query-activated hubs) to EvidencePathFinder)`

### Low / loose ends

**L1 — Projection fact mechanism skips hub-endpoint facts.** `projection.py:76-87` derives note sets from contains-derived strengths (traversal-eligible only); a fact with a date/pronoun/hub endpoint (e.g. `scheduled_for` → date) contributes no projection edge or fact_ids even though provenance (`source_note_ids`) is available. `Status: fixed` (when one endpoint has no contains-derived notes the fact edge's `source_note_ids` provenance stands in for it, carrying `fact_ids`; dates-only facts still contribute nothing)

**L2 — Degree cap enforced during the spanning-forest phase.** `projection.py:150-157` skips forest edges once an endpoint hits max degree — a hub note bridging >12 components leaves the rest disconnected, exactly what MSF-first was meant to avoid. `Status: fixed` (the spanning-forest phase is now pure — the degree cap applies only in the fill phase; a hub note bridging 14 components keeps the map connected, tested)

**L3 — `core/repair_enrich.py:40` calls removed `Index.rebuild_for`** → `AttributeError` on first use. Dead script. `Status: fixed` (deleted)

**L4 — `remove_source` mutates an "immutable" generation in place keeping its `build_id`** (`runtime.py:181-198`, `knowledge_store.py:1196-1221`); stale `graph_hash`, weakens snapshot identity. Documented accepted trade. `Status: accepted (document only)`

**L5 — Overlap-straddling mentions/assertions silently dropped.** `build.py:242-244, 285` require single-passage containment; spec §6.4 allows two adjacent overlapping passages sharing the assertion. Low frequency, no counter/log. `Status: fixed` (`_passage_for_span` accepts an adjacent-ordinal overlapping pair whose union contains the span, records the earlier passage, and logs the straddle count; W2-E added the `BuildReport.straddling_span_count` field)

**L6 — Same-span/different-etype endpoint collision.** `build.py:265` keys `resolved_by_note_span` without etype; a span tagged both `organization` and `product` binds fact endpoints to a hash-arbitrary type. `Status: fixed` (`resolved_by_note_span` keeps every etype per span; `_resolve_endpoint` binds deterministically — named types over `concept`, then alphabetical)

**L7 — Tuple-form GLiNER relations get confidence 1.0.** `extract.py:470-472` (and bare-string spans at `:506-508`) default to 1.0, sailing over every threshold into active facts; should fail closed (0.0). `Status: fixed` (both legacy shapes now default to confidence 0.0 and fail the floors)

## Part 4 — Data-management verdict

- **Stale/orphan state (G7): structurally solved** — fresh DB per build, FK cascades, invariant validation (zero orphan entities, no fact-embeddings without facts, no self-facts) before activation; instant `remove_source` cascades correctly with documented df staleness. Residual gaps: L25 (temp sweep), L8 (corrupt cache row), unbounded cache growth.
- **Invalid/short/irrelevant notes: thinner than intended.** Empty notes degrade harmlessly; real gating is connector-side only. No salience/value gating at build time (M4): junk notes get full extraction and graph participation. Decision 2026-07-10: implement salience-based extraction gating (stricter than raw length) per the fixes spec.
- **Entities/subnodes:** non-destructive canonicalization, digit/type guards, pronoun/date/df hub gating, candidate-vs-active statuses all correct — but H1, L6, L18, M13 mean entity data quality does not yet meet §18.2.

## Part 5 — Retrieval verdict

The architecture is the spec (heads with floors, two-stage abstention, true query-to-triple seeding, whole-corpus passage reset, dangling-correct typed PPR, provenance paths, rerank+MMR, registry, six-stage validation). As wired it is undermined by C2 (chat tools), H6 (cap ordering), H-B2 (no isolation), M7 (reset double count), and P1 (unfitted floors). The audit's core question — does filler abstain while real queries retrieve — remains empirically unanswered until P1 runs.
